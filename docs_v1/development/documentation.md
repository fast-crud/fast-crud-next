# 文档维护约定

文档和代码属于同一个交付物。新功能完成后，必须同步说明如何集成、如何配置和如何验证。

## 新功能流程

1. 在实现附近补充聚焦测试。
2. 在 `docs/` 中按职责选择模块：集成放 `getting-started`，配置和行为放 `concepts`，主题放 `themes`，示例页面放 `demos`。
3. 文档至少包含一个可运行的 TypeScript 或 Vue 示例，并说明必要的前置条件。
4. 在 `docs/README.md` 增加入口链接；如果是用户首次接触的能力，再在根 README 增加一句简要说明。
5. 检查相对链接、文件路径、命令和示例 API 与当前源码一致。

## 文档边界

- 根 README：项目定位、安装、启动、最小集成和文档入口。
- `docs/`：完整使用说明、配置细节、主题和示例。
- 包内 README：包级别的短说明；不要复制一整套根文档。
- `IMPROVEMENTS.md`：开发中发现的设计摩擦和待优化项，不替代用户使用文档。

## 验证

文档改动至少检查：

```sh
npm test
```

构建需要进入被修改的包目录执行 `npm run build`。如果示例依赖某个 admin 项目，还应在对应目录运行构建，并在浏览器打开文档中的 URL 验证页面行为。
